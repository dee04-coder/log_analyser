Active Security Detection Rules Logic

The SIEM engine dynamically correlates login telemetry using window-based temporal analysis. Below are the rules running in python/JS logic equivalent to SQL window functions:

HIGH SEVERITY RULE_01

Repeated Failed Logins (Brute Force)

Triggers when 5 or more consecutive/cumulative failed logins occur for a single user account within a 10-minute sliding window.

# SQLite Window Logic
SELECT username, COUNT(*) 
FROM logs 
WHERE status='Failure' 
GROUP BY username, strftime('%Y-%m-%d %H:%M', timestamp)
HAVING COUNT(*) >= 5;
CRITICAL SEVERITY RULE_02

Successful Login After Repeated Failures

Highlights potential account compromise or password guessing where a successful login occurs within 15 mins following 3+ failed attempts.

# Account Takeover Rule
failures = count_failures(user, last_15_mins)
if failures >= 3 and current_status == "Success":
    trigger_alert("Potential Account Compromise")
MEDIUM SEVERITY RULE_03

Password Spraying (Multi-Account IP)

Flags a single IP address attempting logins across 3 or more distinct usernames within a 10-minute timeframe.

# IP Multi-Target Spray Rule
unique_users = count_distinct_users(ip, window='10m')
if unique_users >= 3:
    trigger_alert("Password Spray Attack Detected")
LOW SEVERITY RULE_04

Out-of-Hours / Geolocation Anomaly

Highlights logins from non-standard locations or during atypical off-hours (e.g. 01:00 - 05:00 UTC) for manual review.

# Anomaly heuristic
if log.hour in [1,2,3,4] or log.country in SUSPICIOUS_LIST:
    flag_anomaly("Atypical Login Context")
